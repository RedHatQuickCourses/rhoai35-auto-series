In this lesson, we will focus on how to inspect a completed run using the visual pipeline and the Playground, and how to export your chosen pattern into an application.

Achieving a high rank on the leaderboard is a great milestone, but you should never ship a pattern based solely on a number. AutoRAG provides two distinct ways to inspect a run before you commit, and two ways to export the pattern you choose.

First, let’s look at the visual pipeline. Earlier versions of AutoRAG represented a run as a single opaque line, which made troubleshooting difficult. OpenShift AI 3.5 replaces that with a full visual pipeline—a diagram showing every stage of the run. When a process succeeds, you will see a satisfying green path. More importantly, when a failure occurs, this diagram shows you exactly which step broke and what it reported. For any user, this is the difference between efficient debugging and guessing.

Next, we have the "Try this pattern" feature in the Playground. This is often cited as the most helpful tool because it eliminates the frustration of exporting a pattern and wiring it up elsewhere only to discover it doesn't meet your needs. 

From the leaderboard, select "Try this pattern" on any ranked configuration. This opens an interactive chat panel grounded in your document vector store, right inside OpenShift AI. You can ask real questions and watch how the system answers. You can even see exactly which chunks were retrieved and where they originated. This allows you to judge not just the answer, but the evidence behind it. You can even switch between candidate patterns live to compare them side-by-side.

A useful tip: before you export anything, test the pattern with a few of your own tricky questions. If the system retrieves sensible chunks and grounds its answers effectively, you have validated the pattern without writing a single line of code.

When you are satisfied with a pattern, it is time to export it. You have two main options.

First, you can click "View code" to access an application-ready snippet that calls the OGX Responses API endpoint. You can choose from cURL, Python, Go, or Node.js. These snippets call the slash v-one slash responses endpoint directly, allowing your application to receive grounded answers without you needing to build the retrieval plumbing yourself.

Second, if you prefer a hands-on approach, AutoRAG can generate two self-contained Jupyter notebooks: an indexing notebook and an inference notebook. You can run these inside an OpenShift AI workbench to reproduce, audit, or batch-score the pattern locally. 

Keep in mind that governance still applies here. The system instruction you settle on for your RAG application can be versioned in the MLflow Prompt Registry, ensuring that both your production-grade prompt and your retrieval pattern remain under proper control.

This will allow AutoRAG to automatically generate and score prompt candidates against your evaluation questions, essentially providing automated prompt engineering layered on top of the automated retrieval tuning you have explored here.
