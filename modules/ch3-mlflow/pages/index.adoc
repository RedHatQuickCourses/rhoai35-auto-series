= Prompt Engineering and MLflow Governance

Goal::

Transition from predictive data to generative text, leveraging the GenAI Studio Playground and MLflow to version, track, and eliminate "prompt drift".

So far this course has lived in the world of *numbers*: rows, columns, and a target value you wanted to predict. This chapter is where we cross over into *text*. Same platform, same governance instincts you built in chapters 1 and 2, but now the thing you're shaping is a prompt to a large language model instead of a tabular prediction.

Here's the mindset shift worth making up front. When you worked with AutoML, you never would have shipped a model without a leaderboard, feature importance, and a version in the registry. Yet the industry's default habit with prompts is the opposite: a clever instruction gets typed into a text box, copied into some code, tweaked by a teammate, pasted into a notebook, and six weeks later nobody can say which version is actually running in production. That sprawl has a name, *prompt drift*, and it's exactly the kind of chaos this chapter teaches you to prevent.

It helps to see where this fits in the bigger picture. Think of enterprise GenAI as an escalation ladder, and prompt governance is the second rung:

[source]
----
[1. Predictive Baseline] ──► [2. Prompt Governance] ──► [3. Context Grounding] ──► [4. Model Customization] ──► [5. Operational Safety]
      (AutoML)                (Playground + MLflow)          (AutoRAG)              (Fine-Tuning)              (Guardrails)
----

You've already got rung 1. Over the next few pages we'll cover rung 2 in three moves: testing prompts interactively in the *GenAI Studio Playground*, treating those prompts as versioned *code* rather than throwaway text, and using *MLflow* to govern them across your whole organization. Rung 3, AutoRAG, is the very next chapter.
