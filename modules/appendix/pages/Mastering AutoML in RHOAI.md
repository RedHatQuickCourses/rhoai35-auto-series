# Module 1: Predictive Foundations (AutoML) This module introduces **AutoML in Red Hat OpenShift AI (RHOAI) 3.5+** as the fastest path from raw enterprise data to production-ready predictive models 1, 2\. Designed for technical practitioners (data scientists, AI engineers, and solution architects), this content focuses on evaluating when and how to apply AutoML, understanding the underlying algorithms, and utilizing evaluation artifacts for governance and deployment—without getting bogged down in platform cluster administration 3-5. \--- \#\# 1\. Executive Narrative & The Business Case At the leadership level, traditional machine learning projects frequently suffer from multi-month development cycles and "PoC Death," where models fail to transition from experimental notebooks into active production 6, 7\. AutoML transforms this dynamic by automating data preparation, feature engineering, algorithm selection, and ensembling 2, 4\. \* **70–80% Faster Time-to-Market:** Compresses model development cycles from 3–6 months down to a matter of hours, turning multi-quarter R\&D efforts into same-week operational delivery 6, 8, 9\. \* **3x Workforce Multiplier:** Empowers software engineers, data analysts, and IT practitioners to construct high-accuracy predictive baselines without competing for scarce specialized resources 6, 9\. \* **The "Sorting Hat" Metaphor:** AutoML acts as an automated sorting system 10, 11\. You feed raw tabular CSV data pulled from S3 storage into the pipeline, and the platform processes the patterns to output a ranked leaderboard of candidate models ready for promotion 2, 10, 11\. \* **Eliminating "PoC Death":** Rather than leaving code stranded in disconnected environments, AutoML generates standardized deployment artifacts that move directly to production endpoints 6, 12, 13\. \--- \#\# 2\. Predictive AI vs. LLMs: Sizing & Infrastructure Economics A critical part of the foundational review is establishing **where predictive AI fits in an enterprise portfolio** relative to Large Language Models (LLMs) 10, 14, 15\. | Dimension | Predictive Models (AutoML / Tabular) | Large Language Models (LLMs) | | :--- | :--- | :--- | | **Primary Scope** | Narrow, single-task structured decisions (e.g., churn, fraud, pricing) 14, 16 | Broad, open-domain reasoning and unstructured text generation 14, 16 | | **Input Structure** | Low-dimensional structured tabular data (10–100+ features) 14, 16 | High-dimensional unstructured text across billions of tokens 14, 16 | | **Footprint & Artifact Size** | **Kilobytes to Megabytes** (lightweight decision trees / ensembles) 14, 16, 17 | **Tens to Hundreds of Gigabytes** (billions of parameters) 14, 16 | | **Hardware & Compute** | **Lightweight CPU infrastructure** (no specialized GPUs required) 9, 14, 17 | High-VRAM GPU clusters 14, 16 | | **Execution Latency** | **Microsecond inference** for high-throughput operational systems 16, 17 | Second-level response latency 14, 18 | | **Auditability** | Deterministic decision logic with clear feature importance metrics 9, 17 | Probabilistic reasoning requiring complex guardrail evaluation 17, 19 | **Key Takeaway:** Predictive models are cheap, fast, and deterministic 17, 20\. They execute high-throughput scoring on existing CPU clusters at a fraction of the infrastructure cost required by GPU-hungry LLMs 9, 17\. \--- \#\# 3\. Data Qualification: When is AutoML the Right Choice? Before initiating an AutoML run, practitioners must evaluate whether the available dataset qualifies for automated predictive modeling 21, 22: 1\. **Tabular Structure:** Data is stored in CSV format with rows representing distinct entities and columns representing historical attributes 22, 23\. Files must be UTF-8 encoded with comma delimiters and a header row (up to 32 MiB via the dashboard UI, or up to 100 MB when ingested from S3) 23-25. 2\. **Clear Target Label:** The dataset includes a single ground-truth target column holding historical answers to predict for new data 21, 22\. 3\. **Feature Diversity:** A mix of numerical metrics and categorical text labels where automated feature type inference, missing value imputation, and categorical encoding provide immediate value 22, 26, 27\. 4\. **Data Volume:** At least 500 to 1,000+ rows for prototyping, with 10,000+ rows typical for enterprise production evaluation 22\. \#\#\# When AutoML is NOT the Tool \* **Unstructured Media:** Computer vision, audio, or raw video tasks (which require specialized deep learning pipelines) 28, 29\. \* **Open-Ended Text Generation:** Generative conversational tasks or document synthesis (which belong to AutoRAG and LLMs) 28, 29\. \* **Custom Domain Edge Cases:** Scenarios requiring manual feature engineering for proprietary business rules that cannot be inferred from raw tables 15, 29\. \--- \#\# 4\. The 4 Prediction Task Types & UI Recommendations Every predictive problem maps to one of four core task types 30, 31\. When a CSV dataset is loaded into the Red Hat OpenShift AI dashboard UI, the system infers column types and recommends the appropriate task type and default optimization metric 2, 21, 32\.  Raw CSV Data Ingestion │ ├── Target has 2 unique values ─────────► Binary Classification ("Yes/No?") ├── Target has 3+ text categories ──────► Multiclass Classification ("Pick 1 from Menu") ├── Target contains continuous numbers ──► Regression ("How Much?") └── Target tied to Timestamp \+ ID ──────► Time Series Forecasting ("What's Next over Time?")  \#\#\# 1\. Binary Classification \* **Memory Trick:** *"Yes or No?"* or *"This or That?"* 30, 31 \* **Data Cue:** Target column contains exactly **2 unique values** (e.g., 0/1, True/False, Churn/No-Churn) 21, 30, 31\. \* **Use Cases:** Customer churn prevention, fraud detection, credit risk approval 30, 31, 33\. \* **Default Optimization Metric:** **Accuracy** (Switch to **ROC-AUC** or **F1 Score** for imbalanced datasets such as 99% non-fraud / 1% fraud) 31, 32\. \#\#\# 2\. Multiclass Classification \* **Memory Trick:** *"Pick 1 from a Menu"* 30, 31 \* **Data Cue:** Target column contains **3 or more distinct text categories or labels** 21, 30, 31\. \* **Use Cases:** Support ticket routing, customer segmentation, industrial equipment failure type classification 30, 31, 33\. \* **Default Optimization Metric:** **Accuracy** 31, 32\. \#\#\# 3\. Regression \* **Memory Trick:** *"How Much?"* or *"How Many?"* 30, 31 \* **Data Cue:** Target column contains **continuous numerical values** without explicit time trends 21, 30, 31\. \* **Use Cases:** Continuous price estimation, medical charge prediction, operational duration forecasting 30, 31\. \* **Default Optimization Metric:** **\\\\(R^2\\\\) (R-Squared)** (measures variance explained on a 0.0 to 1.0 scale) 31, 32, 34\. \#\#\# 4\. Time Series Forecasting \* **Memory Trick:** *"What's Next Over Time?"* 30, 31 \* **Data Cue:** Dataset includes a **Timestamp column**, an **ID column** identifying each sequence, and a numeric **Target column** 21, 30, 35\. \* **Use Cases:** Retail inventory demand forecasting, quarterly sales projections, capacity planning 30, 31, 33\. \* **Default Optimization Metric:** **MASE (Mean Absolute Scaled Error)** (evaluates forecast accuracy relative to a simple naive baseline; higher negated values indicate superior performance) 31, 32, 36\. \--- \#\# 5\. Need-to-Know Algorithms & Automated Ensembling Under the hood, RHOAI AutoML uses **AutoGluon** as its meta-orchestrator 2, 4, 37\. Rather than forcing a data scientist to manually test single algorithms, AutoML executes parallel sweeps across two primary model families 2, 4, 27: \#\#\# "Smart Flowchart Builders" (Gradient Boosted Decision Trees) \* **XGBoost:** The meticulous veteran. Uses exact depth-wise tree splits; ideal for standard spreadsheet data and financial records 38-40. \* **LightGBM:** The speed demon. Created by Microsoft; uses fast histogram-based leaf-wise splitting to process multi-gigabyte datasets with low memory overhead 38-40. \* **CatBoost:** The category specialist. Created by Yandex; natively processes categorical text labels without requiring manual one-hot encoding 38-40. \#\#\# "Synthetic Brains" (Deep Neural Networks) \* **Tabular MLPs (PyTorch / FastAI):** Trains Multi-Layer Perceptrons to capture complex non-linear feature interactions across tabular columns 37, 38, 40\. \#\#\# Multi-Layer Stacked Ensembling (WeightedEnsemble) Rather than simply picking one winning algorithm, AutoGluon combines the predictions of top candidate models into a multi-layer **Weighted Ensemble** 2, 4, 26\. This stacked approach consistently outperforms single-model hyperparameter tuning by **2–5% in accuracy** 26, 41, 42\. \--- \#\# 6\. Processing Data in RHOAI & Evaluation Artifacts Once an optimization run completes, RHOAI aggregates generated Kubeflow Pipeline artifacts into the dashboard UI to provide full model explainability and auditability 12, 43, 44:  Raw CSV Ingestion (S3) ──► Automated Pipeline ──► Interactive Leaderboard ──► Model Evaluation Artifacts ──► KServe REST Endpoint  1\. **The Interactive Leaderboard:** Displays all trained candidate models ranked by the primary optimization metric, alongside secondary metrics, fit times, and inference latencies 43, 45\. 2\. **Feature Importance Rankings:** Permutates column values to quantify which input variables drive predictions 46, 47\. Helps data scientists verify explainability, validate business logic, and detect accidental data leakage 12, 43, 46\. 3\. **Confusion Matrix:** Displays actual vs. predicted class distributions in a 2x2 or multi-class grid to pinpoint exact classification errors (True Positives, False Positives, False Negatives, True Negatives) 43, 46, 48\. 4\. **ROC & Precision-Recall Curves:** Visualizes model separation and precision/recall trade-offs across decision thresholds, enabling teams to calibrate business rules (e.g., fraud sensitivity) 43, 46, 49\. 5\. **Time Series Backtesting:** Displays forecast error trends across rolling validation windows and compares predicted vs. observed values for best/worst performing windows 43, 50, 51\. 6\. **Auto-Generated Jupyter Notebook:** Clicking **"Save notebook"** exports a Python notebook containing pre-written code to connect to S3, load the trained predictor, and perform batch scoring or custom validation 12, 52, 53\. 7\. **Production Handoff:** \* **Register:** Promote the winning model version directly to the **RHOAI Model Registry** 12, 54\. \* **Deploy:** Deploy the model using the **AutoGluon ServingRuntime for KServe** to instantly expose a scalable, production REST API endpoint (/v2/models//infer) 12, 54, 55\. \--- 🎯 **Next Step Idea:** Would you like to draft the exact slide-by-slide presentation deck (or interactive Arcade script) for Module 1, or shall we move on to structuring Module 2 on GenAI Prompting & MLflow Governance?
