In this section we'll learn how to read the leaderboard and the evaluation artifacts, so you can validate a model's business logic before you move it into production.

When a run finishes, OpenShift AI gathers everything the pipeline produced and lays it out in the dashboard as a set of connected views. Together, they're the model's report card. Your job is to ask each artifact a question and make sure the answers string together before you trust the model with a real decision.

Let's start with the leaderboard, your starting point. It lists every candidate model Auto M L trained, ranked by the primary optimization metric for your task, the Accuracy, R-squared, or MASE you met in chapter one. But don't stop at the ranking column. The leaderboard also shows secondary metrics, fit times, and inference latencies, and those extra columns often decide the real winner. Keep in mind the top-ranked model isn't automatically the one to ship. If the number-one model scores a hair higher but takes ten times longer to return a prediction, a slightly lower-ranked model with microsecond latency may be the smarter production choice. Read across the row, not just down the rank.

Next, feature importance. This is the artifact that separates "the model scored well" from "the model is trustworthy." It works by shuffling each column's values and measuring how much the model's performance drops, which tells you how much the model actually leans on that input. Use it to answer three questions. First, does this match reality? If a churn model's top signals are "months since last login" and "support tickets opened," that lines up with business intuition. Second, is there anything suspicious? A single feature that dominates everything else is a classic red flag for data leakage, where a column, say a "cancellation date," accidentally hands the model the answer. The model looks brilliant in testing and then falls apart in production. Third, can you explain this to a stakeholder? Feature importance is how you turn a model into a story a business owner will actually believe. One tip: make feature importance the first thing you look at after the score, not the last. Catching a leaked column here saves you from deploying a model that's secretly cheating.

For classification tasks, the confusion matrix lays out actual versus predicted classes in a grid: true positives, false positives, false negatives, and true negatives. It moves you past a single accuracy number and shows you which mistakes the model makes. And that distinction is often a business decision in disguise. In fraud detection, a false negative, missing real fraud, usually costs far more than a false positive, flagging a legitimate charge for review. The matrix lets you see that trade-off in black and white instead of hoping the headline accuracy has it covered.

You can calibrate those trade-offs with the ROC and Precision-Recall curves. These show how the model separates classes across every possible decision threshold, not just the default cutoff. Think of them as your control dial: turn the fraud model's sensitivity up and you catch more fraud but annoy more legitimate customers with reviews; turn it down and the reverse. The curves let you pick the operating point that matches what your organization actually cares about.

If you're working with forecasting models, you'll use time series backtesting. Because time only runs one direction, there's no single test set, so OpenShift AI does rolling backtesting: it walks the model forward through successive validation windows and charts how the forecast error behaves. By comparing predicted versus observed values in the best and worst windows, you can quickly tell whether a model is reliably useful or just got lucky in one quarter.

Here's the thing: none of these views is decisive on its own. A model earns promotion when the story is consistent, a strong leaderboard metric, feature importance that matches reality with no leakage, an error profile you can live with, and, for forecasts, stable behavior across backtests. Read them together and you're validating business logic, not just chasing a score.
