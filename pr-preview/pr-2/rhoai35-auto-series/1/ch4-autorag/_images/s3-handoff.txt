In this section, we'll inspect a completed run using the visual pipeline and the Playground, and then export your chosen pattern into an application.

A high rank on the leaderboard is a milestone, but you should never ship a pattern on the strength of a number alone. Auto RAG gives you two ways to inspect a run before you commit, and two ways to export the pattern you choose.

Start with the visual pipeline. Earlier versions of Auto RAG showed a run as a single opaque line, which made troubleshooting hard. OpenShift AI 3.5 replaces that with a full visual pipeline, a diagram of every stage in the run. When everything works, you get a satisfying green path. More importantly, when something fails, the diagram shows you exactly which step broke and what it reported. That's the difference between debugging efficiently and guessing.

Next is the Try this pattern feature in the Playground. People often call this the most helpful tool, because it saves you from exporting a pattern, wiring it up elsewhere, and only then discovering it doesn't meet your needs. From the leaderboard, select Try this pattern on any ranked configuration. That opens an interactive chat panel grounded in your document vector store, right inside OpenShift AI. You can ask real questions and watch how the system answers. You can even see which chunks were retrieved and where they came from, so you're judging not just the answer but the evidence behind it. And you can switch between candidate patterns live to compare them side by side.

A tip: before you export anything, test the pattern with a few of your own tricky questions. If it retrieves sensible chunks and grounds its answers well, you've validated the pattern without writing a single line of code.

When you're satisfied, it's time to export, and you have two main options. First, click View code for an application-ready snippet that calls the OGX Responses API endpoint. You can choose cURL, Python, Go, or Node.js. These snippets call the slash v-one slash responses endpoint directly, so your application gets grounded answers without you building the retrieval plumbing yourself. Second, if you'd rather get hands-on, Auto RAG can generate two self-contained Jupyter notebooks, an indexing notebook and an inference notebook. Run them in an OpenShift AI workbench to reproduce, audit, or batch-score the pattern locally.

And remember, governance still applies. The system instruction you settle on for your RAG application can be versioned in the MLflow Prompt Registry, so both your production-grade prompt and your retrieval pattern stay under proper control.
