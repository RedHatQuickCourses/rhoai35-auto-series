In this section, we'll treat prompts as code, using Prompt Management in OpenShift AI. By the end you'll see why prompts need version control, and how to use the MLflow-powered registry to version them, give them aliases, and bind them to specific model configurations.

Let's start with the mindset. It's an easy mistake to treat a prompt like a throwaway text string, something you copy, paste, and tweak forever. But a prompt is really a parameter: it shapes how your application behaves just as much as your source code does. So when production results start to regress, it's often impossible to work out which version of a prompt caused it.

Prompt Management, in the dashboard under GenAI Studio and then Prompts, fixes that by giving your prompts a central home. It's powered by the MLflow prompt registry, and it lets you create, version, tag, and reuse prompt templates across your organization. Worth knowing: you'll hear "Prompt Management" and "MLflow prompt registry" used interchangeably. They're the same capability.

Now, versioning, the Git way. The registry works a lot like version control for your instructions. Every time you register a change, it saves a new numbered version, version one, version two, and so on, each with a commit message. Two things make this trustworthy. First, versions are immutable: once saved, a version never changes, so if you need to update a prompt you create a new version, and that's what makes your results reproducible. Second, you can compare versions side by side; the dashboard highlights the differences, so you can see exactly how your wording has evolved.

Then there are aliases, which keep version numbers out of your application code. An alias is a movable label that points to a specific version. You might have a production alias pointing to version two, and a latest alias that always tracks the newest version. Your application references the prompt by its alias, not its version number. So when you're ready to promote version three to production, you just move the production alias to point at it. No code changes, no redeploys. And if you need to roll back, it's a one-click move of the alias back to a known good version.

Before you promote an alias, we really recommend the Playground's Compare view. Load two versions side by side, run the same input against both, and check metrics like latency and token usage to make sure the new version is genuinely an improvement.

A prompt is also more than its text. The registry stores a model configuration right alongside it: the model name, the temperature, the maximum token setting. That keeps the whole recipe, including the specific tuning that prompt needs, together in one place. Prompts can also be bound to specific providers, like Llama, Granite, or Claude, so teams can switch the underlying model without rewriting their prompt code. And if your prompt needs flexibility, use placeholders with double curly braces. You register the reusable shape once; when you load a templated prompt into the Playground, it detects the placeholders and gives you input fields to fill in the runtime values before you run your test.

There's one more layer beyond the prompt itself. Complex experiments often pull in extra pieces, like RAG knowledge sources and connected tools. To capture that whole execution recipe, you can save your session as a Playground Agent. When a teammate opens a saved agent, they don't just get the prompt and temperature; they get the exact model runtime, the same vector store, and the same tool definitions you used. That's true, session-level reproducibility. A note for administrators: Playground Agents are currently a Developer Preview feature and are off by default. You enable them by setting the agent config management flag to true in your dashboard config. Once on, the agents are stored as Kubernetes resources in your project namespace, which makes it easy to collaborate across the team.

To watch the end-to-end flow, registering a prompt, committing a new version, and using the comparison tools, take a look at the interactive demonstrations in the course interface.
