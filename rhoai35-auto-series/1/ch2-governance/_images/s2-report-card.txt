In this module, we will learn how to interpret the leaderboard and evaluation artifacts provided by RHOAI to validate a model's business logic before moving it into production.

When a training run finishes, RHOAI compiles everything the pipeline produced into a set of connected views within the dashboard. Collectively, these act as the model's "report card." Your goal is to examine each of these artifacts, ensuring the information tells a consistent, logical story before you trust the model to make real-world business decisions.

Let's begin with the leaderboard, which serves as your starting point. It lists every candidate model trained by AutoML, ranked by the primary optimization metric for your task—such as accuracy, R-squared, or MASE. However, do not stop at the ranking column alone. The leaderboard also displays secondary metrics, fit times, and inference latencies. These extra columns often determine the true winner. Keep in mind that the top-ranked model isn't automatically the best choice for deployment. If the number-one model scores slightly higher but takes ten times longer to return a prediction, a lower-ranked model with microsecond latency may be the smarter, more practical choice for production. Always read across the row, rather than just down the rank.

Next, we look at feature importance. This is the artifact that distinguishes a model that simply "scored well" from one that is truly trustworthy. Feature importance works by shuffling the values in each column and measuring how much the model's performance drops. This reveals how much the model actually relies on a specific input. Use this view to answer three critical questions: First, does this match reality? If a churn model’s top signals are "months since last login" and "support tickets opened," that aligns with business intuition. Second, is there anything suspicious? A single feature dominating every other input is a classic red flag for data leakage, where a column—like a "cancellation date"—accidentally provides the answer to the model. The model might look brilliant in testing, but it will fail in production. Third, can you explain this to a stakeholder? Feature importance is how you turn a complex model into a narrative that a business owner will believe. A helpful tip here: make feature importance the first thing you review after checking the score; catching a leaked column early saves you from deploying a model that is essentially cheating.

For classification tasks, the confusion matrix lays out actual versus predicted classes in a grid, showing true positives, false positives, false negatives, and true negatives. This moves you beyond a single accuracy number to show exactly where the model is making mistakes. This distinction is often a business decision in disguise. For instance, in fraud detection, a false negative—missing real fraud—usually costs far more than a false positive, where you flag a legitimate charge for review. The matrix allows you to see that trade-off in black and white.

You can further calibrate these trade-offs using ROC and Precision-Recall curves. These visualize how the model separates classes across every possible decision threshold. Think of these curves as your control dial: if you turn up the sensitivity of a fraud model, you catch more fraud but may annoy legitimate customers; turn it down, and the reverse happens. These curves help you pick the operating point that best matches your organization's priorities.

If you are working with forecasting models, you will use time series backtesting. Because time moves in only one direction, RHOAI performs rolling backtesting, walking the model forward through successive validation windows. By charting how the forecast error behaves and comparing predicted versus observed values across both the best and worst windows, you can determine if a model is reliably useful or if it simply got lucky in one specific quarter.

Ultimately, none of these views is decisive on its own. A model earns its promotion to production when the data tells a consistent story: the leaderboard metrics are strong, the feature importance aligns with reality with no signs of data leakage, the error profile is acceptable, and, for forecasts, the behavior is stable over time. By reading these artifacts together, you are validating business logic, not just chasing a high score.

Now that we have reviewed the report card, we are ready to move the model out of the dashboard and into production, following the path from a finished run to a live serving endpoint.
